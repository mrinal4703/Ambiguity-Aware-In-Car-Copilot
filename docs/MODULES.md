## Suggested first deliverable per module
These are starting suggestions drawn from the project PDF; owners should refine them in their own README.

1. **Simulator:** vehicle state, charging stations, calendar and contacts as plain Python objects, with the example tool set from the PDF (`get_vehicle_state`, `search_charging_stations`, `set_navigation`, `send_message`, ...) and reproducible initial states. Push a rough version early: everyone depends on it.
2. **NLU:** fix the known bugs (reflection key mismatch, history resolution, evaluation script), fill the test dataset, emit several candidate interpretations for module 3.
3. **Uncertainty:** turn NLU output into a `BeliefState` with calibrated probabilities; separate "what the user means" from "model's own ability".
4. **EVPI clarification:** see `module_4_evpi/README.md` (starter code included).
5. **Search:** replace the 5-node demo graph with a larger weighted graph; Uniform-Cost Search and A*; time, distance and energy costs.
6. **CSP:** hard constraints (range, connector, deadline, station availability) first, then soft preferences; explain infeasibility.
7. **Planning:** actions with preconditions/effects, dependency ordering, replanning when a station becomes unavailable.
8. **RL:** MDP with the six actions from the PDF, scripted simulated user, tabular Q-learning, the four baseline policies, same safety gate in training and evaluation. Can start against stubs.
9. **Safety:** tool-exists / parameters / preconditions / authorization / confirmation checks, independent of the LLM; verify tool return values before reporting success.
10. **Integration and evaluation:** orchestrator wiring, scenario suite (base, ambiguous, missing capability, unsafe, changing environment), Pass@3 and Pass^3, ablation table.
